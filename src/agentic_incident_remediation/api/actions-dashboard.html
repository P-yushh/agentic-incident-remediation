          Approval policy

          The required reviewer approves or rejects publication in GitHub’s remediation-demo-review environment. “Approve and deploy” authorizes PR creation only, not deployment.

          This dashboard cannot approve, bypass review, merge, or deploy. Workflow cancellation is available only for active runs started here and cannot undo an existing PR. Pause and resume are not supported.

          A successful workflow without a verified receipt is not proof of publication. Missing evidence is never treated as a validation pass. An approved publication receipt does not establish that the PR was merged; post-publication PR review and merge state are not synchronized here.

          Current execution uses fixed synthetic scenarios, not live monitoring. No live cluster metrics, pod logs or events are collected. Validation is a configuration check, not proof of runtime recovery. File comparisons use checked-in reference fixtures, not original snapshots captured from a cluster or repository. Full provenance remains available on each proposal.

          Incident aliases are local display identifiers; original execution IDs and GitHub run numbers remain in provenance. History is stored locally and remote artifacts can expire after one day.
